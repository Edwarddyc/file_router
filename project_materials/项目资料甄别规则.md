# 项目资料甄别规则

## 目标

项目资料甄别包含两个核心能力：

1. **项目背景抽取**：整理项目说明，并识别项目涉及的数据集；
2. **数据集画像**：只对已确认或疑似数据集进行基础定量分析。

文件格式不能直接决定文件是不是数据集。数据集应结合项目背景、文件用途和实际内容判断。

## 处理流程

| 步骤 | 处理内容 | 输出 |
| --- | --- | --- |
| 1. 文件登记 | 记录文件名、格式、大小、位置和哈希 | 文件清单 |
| 2. 背景文档识别 | 找出可能描述项目背景、目标、范围和数据输入的文档 | 背景文档候选 |
| 3. 项目背景抽取 | 整理项目背景信息和预期数据集 | 项目背景草稿、数据集清单 |
| 4. 数据集识别 | 将实际文件与项目背景中的数据集进行匹配 | 已确认、疑似或非数据集文件 |
| 5. 数据集画像 | 对已确认或疑似数据集进行基础定量分析 | 数据集画像 |
| 6. 人工审核 | 审核推断、冲突、缺失和疑似数据集 | 收录、复核或拒绝 |

## 能力一：项目背景抽取

项目背景抽取只整理来源中实际存在的信息。没有出现的信息标记为缺失，不使用模型常识补齐。

### 项目背景信息

| 信息项 | 需要回答的问题 |
| --- | --- |
| 项目标识 | 项目名称、编号或稳定简称是什么？ |
| 项目背景 | 为什么发起项目？当前存在什么问题？ |
| 项目目标 | 项目希望达到什么结果？ |
| 成功标准 | 如何判断项目完成或成功？ |
| 项目范围 | 项目包含和不包含哪些内容？ |
| 参与方 | 客户、团队、负责人和使用者是谁？ |
| 时间与状态 | 项目何时开始？当前处于什么阶段？ |
| 输入资料 | 项目依赖哪些数据、文档或外部输入？ |
| 交付物 | 需要交付哪些文件、系统或结果？ |
| 约束与依赖 | 存在哪些资源、权限、合规、技术限制和外部依赖？ |
| 待确认事项 | 哪些背景信息缺失、冲突或无法确认？ |

### 项目数据集清单

项目背景应尽可能识别以下信息：

| 数据集信息 | 说明 |
| --- | --- |
| 数据集名称 | 项目中使用的正式名称或临时名称 |
| 业务用途 | 数据集在项目中用于什么 |
| 数据来源 | 由谁、哪个系统或哪个流程产生 |
| 预期文件 | 已知文件名、目录或命名规则 |
| 预期格式 | `xlsx`、`csv`、`pdf`、`docx`、`md`、`txt` 等 |
| 数据范围 | 涉及的对象、批次、时间或业务范围 |
| 数据粒度 | 一行或一个记录代表什么 |
| 关键字段 | 已知的标识、时间、指标或关联字段 |
| 更新方式 | 一次性交付、周期更新或持续产生 |
| 当前状态 | 已提供、部分提供、缺失或待确认 |

数据集清单是后续识别实际数据文件的主要依据。

### 信息状态

| 状态 | 含义 | 是否可直接进入正式项目说明 |
| --- | --- | --- |
| `stated` | 来源直接明确陈述 | 是 |
| `inferred` | 可以合理推导，但不是直接陈述 | 否，需审核 |
| `conflicting` | 不同来源说法冲突 | 否，需解决冲突 |
| `missing` | 当前来源没有提供 | 否，登记缺失 |

## 能力二：数据集识别与画像

### 什么是数据集

文件满足以下至少一项时，可作为数据集候选：

- 项目背景明确将其列为输入数据；
- 文件内容由可重复的记录、样本、批次或观测值组成；
- 文件被项目流程用于计算、比较、验证或生成结果；
- 文件属于某个已知数据集的一部分。

以下情况不能仅凭格式认定为数据集：

- Excel 项目计划、人员清单或会议行动项；
- PDF、Word 格式的方案和报告正文；
- Markdown 或 TXT 格式的普通说明文档；
- CSV 格式的配置表或一次性映射表。

它们是否属于数据集，取决于项目用途，而不是扩展名。

### 数据集识别结果

| 结果 | 判断条件 | 后续处理 |
| --- | --- | --- |
| `confirmed-dataset` | 项目背景明确说明，且实际文件能够匹配 | 执行数据集画像 |
| `candidate-dataset` | 内容具有数据记录特征，但背景信息不足 | 执行初步画像并进入人工审核 |
| `dataset-missing` | 项目背景声明需要，但没有找到对应文件 | 登记为数据缺口 |
| `not-dataset` | 文件是背景、方案、会议、结果或其他说明材料 | 不执行数据集画像 |
| `unsupported` | 当前无法可靠读取或判断 | 进入人工审核 |

### 数据集匹配依据

匹配项目数据集与实际文件时，可使用：

- 文件名和目录；
- 文件格式；
- 表名、工作表名和标题；
- 字段名和数据粒度；
- 批次、时间范围或对象范围；
- 文档中对附件和数据文件的明确引用。

只匹配格式或文件名不能直接判定为 `confirmed-dataset`。

### 数据集画像内容

数据集画像只描述实际数据，不生成业务结论，不画图。

#### 通用信息

| 分析项 | 输出 |
| --- | --- |
| 文件组成 | 数据集包含哪些文件、工作表、表格或文档记录 |
| 数据规模 | 文件数、记录数、行列数、页数或文本条目数 |
| 时间范围 | 最早时间、最晚时间及无法识别的时间记录 |
| 可读取情况 | 成功、部分成功、失败及原因 |
| 数据完整性 | 空文件、空表、缺失记录和缺失字段 |
| 重复情况 | 重复文件、重复记录或疑似主键重复 |

#### 表格型数据集

适用于以表格记录为主的数据集：

| 分析项 | 输出 |
| --- | --- |
| 表结构 | 工作表、表名、行数、列数和表头 |
| 字段类型 | 文本、整数、小数、日期、布尔值或混合类型 |
| 缺失情况 | 每列空值数量和比例 |
| 唯一性 | 唯一值数量和疑似主键重复 |
| 数值摘要 | 最小值、最大值、均值和中位数 |
| 分类摘要 | 高频值和分类数量 |
| 异常提示 | 类型混合、空表头、异常单位和极端值候选 |

#### 文档型数据集

仅当 PDF、Word、Markdown 或 TXT 被确认作为数据记录集合使用时执行：

| 分析项 | 输出 |
| --- | --- |
| 文档数量 | 文件和可识别记录数量 |
| 内容规模 | 页数、段落数、字数或字符数 |
| 结构一致性 | 标题、章节、表格和字段是否一致 |
| 重复情况 | 重复文件、重复段落或高度相似记录 |
| 提取覆盖 | 可提取文本、图片文本和不可读取内容的比例 |
| 时间与对象覆盖 | 可识别的时间、对象、批次或主题范围 |

不得在画像阶段判断业务因果、实验成败或数据是否满足验收标准。

## 审核产物与正式资料

Agent 和分析工具的输出先进入审核区，不直接混入正式项目资料：

```text
project_materials/
├── inbox/                       # 待甄别文件
├── review/
│   ├── file-register/           # 所有文件的最低限度登记
│   ├── project-background/      # 项目背景草稿和数据集清单
│   ├── dataset-matches/         # 数据集与实际文件的匹配结果
│   ├── dataset-profiles/        # 仅数据集的画像
│   └── issues/                  # 缺失、冲突和读取失败
└── accepted/
    ├── project.md               # 审核通过的项目说明
    └── sources/                 # 审核通过的原始资料和数据集
```

## 职责边界

Pi Agent 负责：

- 阅读项目背景类文档；
- 抽取项目说明候选信息和数据集清单；
- 结合背景判断实际文件是否可能属于数据集；
- 标记推断、冲突、缺失和需要复核的内容。

确定性程序负责：

- 计算文件大小和哈希；
- 读取表格结构并执行基础统计；
- 生成数据集画像；
- 校验 Agent 输出字段；
- 检测重复文件和重复记录；
- 控制文件移动、覆盖和正式写入。

Pi Agent 不直接删除、覆盖或移动原始文件，也不能仅根据扩展名认定数据集。

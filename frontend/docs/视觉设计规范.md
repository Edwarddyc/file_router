# Context Router 视觉设计规范

> 版本：1.0  
> 风格名称：**Monochrome Signal / 黑白信号式**  
> 适用范围：知识管理、审核工作台、数据摄取、任务路由和后台管理类产品

## 1. 风格概述

这套视觉风格以黑、白和中性灰构成主要界面，只在需要快速识别类别、状态或文件格式的位置使用明亮彩色。

整体气质应当是：

- 冷静而不沉闷；
- 简洁但不空洞；
- 专业且具有轻微的编辑感；
- 信息密度较高，但层级清楚；
- 彩色是“信号”，不是装饰。

一句话定义：

> 用黑白建立秩序，用明亮色彩传递信号。

## 2. 设计原则

### 2.1 黑白承担结构

页面背景、卡片、导航、标题、主要按钮、边框和正文均使用黑白灰。用户在没有颜色的情况下也应能理解页面结构和操作优先级。

### 2.2 彩色承担语义

彩色只用于：

- 文件格式；
- 内容类别；
- 流程阶段；
- 待审核、风险和失败状态；
- 小型指标图标。

大面积背景、主导航和主要操作不使用彩色。

### 2.3 色彩必须明亮

所有语义色采用“明亮色块 + 浅色底 + 同色系深色文字”的组合，不使用大面积深蓝、深紫、墨绿或暗红。

推荐的视觉关系是：

```text
浅色背景 → 明亮标识色 → 较深同色文字
```

### 2.4 一个元素只表达一个信号

不要同时用颜色、渐变、阴影和动画重复强调同一个状态。通常使用以下一种组合即可：

- 浅色底 + 文字；
- 明亮圆点 + 状态文字；
- 明亮图标底 + 中性正文；
- 明亮流程节点 + 灰色连接线。

### 2.5 原始内容优先于装饰

文件名、项目名、状态和判断依据是视觉主角。装饰元素必须弱于内容，不使用插画、复杂纹理和大面积渐变。

## 3. 色彩系统

### 3.1 中性色

| Token | 色值 | 用途 |
| --- | --- | --- |
| `--ink` | `#111111` | 标题、正文、关键数值 |
| `--accent` | `#000000` | 主要按钮、强操作、品牌强调 |
| `--accent-hover` | `#181818` | 黑色按钮悬停状态 |
| `--muted` | `#717171` | 次级说明文字 |
| `--line` | `#E5E5E5` | 卡片和表格分隔线 |
| `--surface` | `#FFFFFF` | 卡片和内容表面 |
| `--soft` | `#F5F5F5` | 页面背景和弱分区 |
| `--sidebar` | `#090909` | 主侧栏背景 |

黑白主体建议占整个界面的 80% 以上。

### 3.2 语义色

每种语义色包含三个层级：

| 色系 | 主色 | 浅色底 | 深色文字 | 推荐语义 |
| --- | --- | --- | --- | --- |
| 蓝色 | `#78B8F5` | `#EDF7FF` | `#376B9B` | 输入、登记、业务知识、信息 |
| 紫色 | `#B39BE8` | `#F5F1FF` | `#6D579D` | 路由、架构、推理、规则 |
| 橙色 | `#F4B469` | `#FFF4E7` | `#9B5F27` | 处理中、待审核、结果、提醒 |
| 暖红 | `#E28B82` | `#FFF0EE` | `#9C4D46` | 问题、风险、失败、冲突 |

语义色建议占界面的 5%—10%，单个大区块不要同时出现四种颜色。

### 3.3 CSS Token

```css
:root {
  --ink: #111111;
  --muted: #717171;
  --line: #e5e5e5;
  --surface: #ffffff;
  --soft: #f5f5f5;

  --accent: #000000;
  --accent-hover: #181818;
  --accent-soft: #f0f0f0;

  --blue: #78b8f5;
  --blue-soft: #edf7ff;
  --blue-ink: #376b9b;

  --violet: #b39be8;
  --violet-soft: #f5f1ff;
  --violet-ink: #6d579d;

  --orange: #f4b469;
  --orange-soft: #fff4e7;
  --orange-ink: #9b5f27;

  --red: #e28b82;
  --red-soft: #fff0ee;
  --red-ink: #9c4d46;
}
```

## 4. 文件格式配色

文件格式通过文件名前方的小型标识块表达。配色根据后缀固定，不根据业务类别变化。

| 文件类型 | 后缀 | 背景 | 边框 | 文字 |
| --- | --- | --- | --- | --- |
| Word | `doc`、`docx` | `#EAF5FF` | `#CCE6FB` | `#3473A8` |
| Excel | `xls`、`xlsx` | `#EAF8EE` | `#CCEBD6` | `#367B4E` |
| CSV | `csv` | `#E8F8F6` | `#C7EBE6` | `#327A70` |
| PDF | `pdf` | `#FFF0EE` | `#F5D4D0` | `#B7564E` |
| Markdown | `md`、`markdown` | `#F4EFFF` | `#E1D5FB` | `#7557AA` |
| PowerPoint | `ppt`、`pptx` | `#FFF3E8` | `#F5DCC5` | `#A75F24` |
| JSON | `json` | `#FFF8DF` | `#F2E3A6` | `#8B6A17` |
| 文本 | `txt`、`log` | `#F2F3F5` | `#DEDFE3` | `#62666D` |
| 压缩包 | `zip`、`rar`、`7z` | `#F1F1F1` | `#D9D9D9` | `#4F4F4F` |

使用规则：

- 标识块只显示大写后缀，不使用产品 Logo；
- 默认尺寸为 `34 × 38px`；
- 圆角为 `7px`；
- 不支持的格式使用中性灰；
- 文件格式色与业务类别色可以同时出现，但应分处不同列，避免混淆。

## 5. 业务类别配色

| 类别 | 颜色策略 | 说明 |
| --- | --- | --- |
| 项目资料 | 黑色或中性灰 | 作为基础证据，不抢占注意力 |
| 业务知识 | 蓝色 | 表示信息、知识和输入 |
| 架构 | 紫色 | 表示结构、设计和推理 |
| 结果 | 橙色 | 表示输出、观察和需要关注的结论 |
| 问题 | 暖红色 | 表示缺失、冲突、风险和待处理事项 |

类别色只出现在：

- 小型标签；
- 分布图条；
- Handler 图标；
- 文件详情中的类别提示。

类别色不应用于整张卡片背景。

## 6. 流程配色

流程组件使用颜色表达阶段，而不是成功或失败：

| 阶段 | 颜色 | 表达方式 |
| --- | --- | --- |
| 已登记 | 明亮蓝色 | 实心圆形节点 |
| 已路由 | 明亮紫色 | 实心圆形节点 |
| 处理中 | 明亮橙色 | 浅橙底、橙色边框和弱光环 |
| 已收录 | 黑灰色 | 中性节点，完成后可转为黑色 |

连接线保持浅灰色。不要制作彩色渐变连接线，否则会削弱节点本身的语义。

## 7. 排版

### 7.1 字体栈

```css
font-family:
  Inter,
  "Segoe UI",
  "PingFang SC",
  "Microsoft YaHei",
  system-ui,
  sans-serif;
```

不依赖远程字体，保证企业内网和本地环境下的稳定性。

### 7.2 字号层级

| 层级 | 建议字号 | 用途 |
| --- | ---: | --- |
| 页面标题 | `20px` | 页面主标题 |
| 模块标题 | `16px` | 卡片和区域标题 |
| 卡片标题 | `13px` | Handler、文件详情标题 |
| 正文 | `11px`—`12px` | 描述和主要操作 |
| 表格正文 | `10px`—`11px` | 高密度信息 |
| 辅助文字 | `8px`—`10px` | 时间、来源、版本和标签 |
| 核心数值 | `22px`—`23px` | 指标卡数值 |

中文字重以 `650` 左右表示重点。避免全页使用粗体。

### 7.3 文字颜色

- 标题与关键内容：`#111111`；
- 次级说明：约 `#717171`；
- 占位和弱提示：约 `#999999`；
- 深色侧栏主文字：白色；
- 深色侧栏次级文字：`#A0A0A0`。

## 8. 布局与空间

### 8.1 页面骨架

```text
240px 固定侧栏
    +
91px 吸顶顶栏
    +
最大 1440px 内容区域
```

桌面端内容区水平内边距为 `34px`，移动端为 `16px`。

### 8.2 间距系统

基础间距单位采用 `4px`，常用值为：

```text
4 / 8 / 12 / 16 / 20 / 24 / 28 / 34
```

- 页面模块之间：`20px`；
- 卡片内部：`18px`—`24px`；
- 图标与文本：`8px`—`14px`；
- 表格单元格：垂直 `13px`；
- 标签内部：水平 `8px`。

## 9. 形状与质感

### 9.1 圆角

| 元素 | 圆角 |
| --- | ---: |
| 页面卡片 | `12px`—`14px` |
| 按钮、输入框 | `8px` |
| 小图标容器 | `8px`—`10px` |
| 标签 | `5px` |
| 状态圆点 | 完全圆形 |

圆角应克制，不使用过度圆润的“胶囊化”卡片。

### 9.2 边框

卡片边框使用 `1px #E5E5E5`。边框负责界定结构，阴影只负责轻微抬升。

### 9.3 阴影

默认卡片阴影：

```css
box-shadow: 0 8px 30px rgba(0, 0, 0, 0.06);
```

禁止使用浓重、彩色或多层发光阴影。只有当前处理中的流程节点可以使用弱暖色光环。

## 10. 核心组件规范

### 10.1 侧栏

- 背景为接近纯黑的 `#090909`；
- Logo 使用白底黑色图形；
- 默认导航文字为中性灰；
- 选中项使用深灰底、白色文字和白色左边线；
- 侧栏不使用蓝、紫或绿色；
- 仅待审核数量允许使用亮橙色圆形徽标。

### 10.2 主要按钮

- 黑底白字；
- 高度不小于 `38px`；
- 悬停时使用 `#181818`；
- 主按钮不使用品牌彩色，避免与状态色混淆。

### 10.3 指标卡

- 白色卡片；
- 核心数值使用黑色；
- 图标容器可以使用浅蓝、浅紫或浅橙；
- 一张卡片只使用一种语义色；
- 彩色面积不应超过卡片面积的 15%。

### 10.4 表格

- 表头使用极浅灰背景；
- 行之间使用细分隔线；
- 悬停只增加轻微灰色背景；
- 文件后缀标识放在最左侧；
- 业务类别放在独立列中，不能用文件后缀色代替；
- 行末使用低对比度箭头表示可进入详情。

### 10.5 标签

标签采用浅色背景与同色系深色文字，不采用实心深色背景。

推荐结构：

```css
.badge {
  min-height: 23px;
  padding: 0 8px;
  border-radius: 5px;
  font-size: 9px;
  font-weight: 650;
}
```

### 10.6 状态

状态由小圆点和文字共同表达：

- 路由中、处理中：中性灰；
- 待审核：橙色；
- 已收录：黑色；
- 失败：暖红色。

不能只依赖颜色判断状态，必须同时显示文字。

### 10.7 抽屉

- 从右侧进入；
- 宽度上限约 `480px`；
- 背景纯白；
- 使用章节分隔线组织信息；
- 底部操作区固定；
- 遮罩为低透明黑色，不使用彩色遮罩。

## 11. 动效

动效只用于帮助理解状态变化：

- 页面进入：`280ms` 淡入并向上移动 `4px`；
- 按钮悬停：`180ms`；
- 侧栏展开：约 `220ms`；
- 抽屉进入：约 `250ms`；
- 主要按钮悬停可以上移 `1px`。

不使用循环动画、弹跳动画或大幅缩放。

## 12. 响应式规则

### 大于 1080px

- 四列指标卡；
- 总览双栏；
- Handler 三列布局；
- 固定侧栏。

### 761px—1080px

- 指标卡两列；
- 总览改为单栏；
- Handler 两列；
- 摄取说明可隐藏。

### 小于等于 760px

- 侧栏改为抽屉式；
- 内容边距缩小；
- Handler 单列；
- 表格保留最小宽度并允许横向滚动；
- 不将高密度表格强行压缩为无法阅读的卡片。

## 13. 可访问性

- 所有交互元素必须具备键盘焦点；
- 焦点轮廓使用半透明黑色，不依赖彩色；
- 状态必须包含文字，不允许只显示圆点；
- 亮色背景上的文字使用对应的深色 `ink`，避免白字对比不足；
- 可点击表格行需要支持 `Enter`；
- 图标按钮必须提供 `aria-label`；
- 动效应保持短促，并避免依赖动画表达唯一信息。

## 14. 使用禁忌

不要：

- 将蓝、紫、橙或红色用作大面积页面背景；
- 为每张卡片随机选择颜色；
- 在黑色侧栏中加入多种彩色文字；
- 使用暗色语义色块搭配白字；
- 同一个状态在不同页面使用不同颜色；
- 用业务类别色覆盖文件格式色；
- 使用渐变、玻璃高光、霓虹光和高饱和阴影；
- 为了“活泼”而牺牲表格的可读性。

可以：

- 使用亮色小面积强调流程节点；
- 使用浅色标签帮助扫描；
- 使用文件后缀色快速识别格式；
- 使用黑色建立最强操作层级；
- 使用灰色安静地承载大量信息。

## 15. 新页面复用步骤

新增页面时按以下顺序设计：

1. 先只用黑白灰完成布局和信息层级；
2. 确定页面中真正需要快速识别的语义信号；
3. 从蓝、紫、橙、暖红中选择最多两种强调色；
4. 优先使用浅色底标签或小型图标容器；
5. 检查移除颜色后页面是否仍可理解；
6. 检查颜色是否与全局语义一致；
7. 在桌面端和移动端分别确认信息密度。

## 16. 交付检查清单

- [ ] 页面主体是否仍以黑白灰为主；
- [ ] 彩色是否只出现在标识和状态区域；
- [ ] 彩色色块是否足够明亮；
- [ ] 相同语义是否使用相同颜色；
- [ ] 文件后缀是否使用固定配色；
- [ ] 颜色之外是否有文字或图形辅助表达；
- [ ] 主要按钮是否保持黑底白字；
- [ ] 侧栏是否保持纯黑白灰；
- [ ] 卡片边框和阴影是否足够克制；
- [ ] 移动端是否仍然清晰可操作。

## 17. 设计记忆点

这套风格最需要被保留的不是某一个具体色值，而是以下关系：

```text
黑色侧栏建立边界
白色内容区提供呼吸感
细灰线组织高密度信息
明亮小色块承担语义识别
文件后缀颜色负责格式识别
黑色按钮负责主要行动
```

只要这些关系不变，即使在其他项目中微调色值、字体或间距，仍然可以保持一致的“Monochrome Signal”视觉气质。
